## Kaggle 部署排障：numpy 2 不兼容
- 现象：Kaggle 上运行 tools/train.py，报 `_ARRAY_API not found`（torchvision 导入崩）+ matplotlib backend `module://matplotlib_inline.backend_inline` 无效。
- 根因：py39 环境里 numpy 被升到 2.0.2，而 torch 1.13.1 / torchvision 0.14.1 / mmcv-full 1.7.2 均基于 numpy 1.x 编译；matplotlib-inline 包缺失导致连锁报错。
- 修复：`pip install "numpy<2" matplotlib-inline`（py3.9 上最后 1.x 为 numpy 1.26.4）+ 重启 session；train.py 顶部加 `os.environ["MPLBACKEND"]="agg"`。
- 项目约束：README 明确要求 python 3.9.17（mmrotate 0.3.4 官方仅支持 py≤3.9），Kaggle 部署应保持 py3.9，勿用官方镜像默认 py3.10+；勿升级 torch（mmcv 1.7.2 只支持到 torch 1.13）。

## Kaggle 训练报错修复：LoadImageFromFile 不支持 spectrals
- 现象：Kaggle 跑 tools/train.py 报 `TypeError: LoadImageFromFile: __init__() got an unexpected keyword argument 'spectrals'`（DroneVehicleDataset 构建 pipeline 时）。
- 根因：config 的 train pipeline 写成 `dict(type='LoadImageFromFile', spectrals=(...))`；LoadImageFromFile 是 mmdet 内置类不支持 spectrals，支持该参数的是项目自定义 `LoadImagePairFromFile`（mmrotate/datasets/pipelines/loading.py，注册于 ROTATED_PIPELINES，双光谱可见光+红外加载）。
- 修复（本地已改，需同步 Kaggle）：
  - 根目录 lsk_s_fpn_1x_dota_le90.py：train 两处 LoadImageFromFile→LoadImagePairFromFile；val/test 三处 spectrals=('rgb','ir')→('visible','infrared')（img_prefix 是 .../visible/，内部靠 replace(visible,infrared) 定位红外图，写 rgb/ir 不会替换）。
  - tools/cfg/lsk_s_fpn_1x_dota_le90.py 同款问题一并修复。
- 注意：若只想单模态训练应写 `dict(type='LoadImageFromFile')`（不带 spectrals）；tools/cfg/dronevehicle_m.py 第20行也有同类问题待处理。
- 追加：tools/cfg/dronevehicle_m.py 已修复（train 第20行 LoadImageFromFile→LoadImagePairFromFile；test 第29行 spectrals ('rgb','ir')→('visible','infrared')）。全项目扫描确认无其他生效配置存在同类问题（仅剩日志/注释/build 产物中的旧写法）。
