## Kaggle 训练报错修复：标注格式不匹配（YOLO vs DOTA）→ 0 样本
- 现象：Kaggle 跑 train 报 `ValueError: need at least one array to concatenate`（mmdet group_sampler.py:36）。
- 根因链：标注 txt 实际是 **YOLO 格式**（5 列：`cls_id cx cy w h`，归一化），而 DroneVehicleDataset.load_annotations 按 **DOTA 格式**（10 列：4点+类别+难度）解析 → `poly2obb_np` 解包 8 坐标失败被 `except: continue` 静默吞掉 → 每图 gt 为空 → `filter_empty_gt` 过滤全部 2000 张 → 数据集 0 样本 → GroupSampler 对空数组 concatenate 报错。
- 修复（mmrotate/datasets/dronevehicle.py，本地已改需同步 Kaggle）：
  - load_annotations 按首行列数探测格式：5 列走 YOLO 分支（cls_id 直接作 label，cx/cy/w/h×图片尺寸反归一化，angle=0 水平框，并生成 polygon）；≥10 列走原 DOTA 分支；其他列数显式抛 ValueError 不再静默。
  - 新增 `_get_img_size()`：PIL 只读 header 取宽高，失败回退 cv2。
- 验证：venv39 实测训练集 len=2000，ann 键 bboxes/labels/polygons 与 eval_rbbox_map（用 ann['bboxes']/ann['labels']）兼容。
- 注意：标注无角度信息，统一按水平框（le90 angle=0）处理；如官方评估按旋转框，后续需另行处理角度来源。

## CUDA OOM 诊断（Kaggle 训练）
- 定位：本地 20260826_221955.log 是 CPU 版 torch（1.13.1+cpu），OOM 发生在 Kaggle GPU（P100/T4 16GB）。
- 结论：非内存泄漏，是"代码设计耗显存 + 配置超标"共同导致。
  - 大头 1：FusionNet/Encoder 把 512 通道注意特征 F.interpolate 到全分辨率 736×864（3×512×736×864×4B ≈ 4GB/样本），再在全分辨率上跑 block1(4→64ch)/conv2(512→128)/block2(→2ch) + SSIM/拉普拉斯损失。
  - 大头 2：extract_feat 中 LSKNet backbone 对 OD_RGB 和 OD_IR 各跑一遍（双光谱设计所需，激活翻倍）。
  - 小浪费：img_fields 6 个张量中 F_rgb/F_ir 与 OD_RGB/OD_IR 数据重复，多占 ~60MB/batch。
  - 配置：samples_per_gpu=4 对这套模型太激进（官方 LSKNet-S+Oriented R-CNN 在 DOTA 上 batch 2）。
- 修复优先级：① samples_per_gpu 4→2/1、workers 8→4；② config 加 fp16=dict(loss_scale=512.)（mmcv 1.7.2 支持 AMP）；③ 代码级：Encoder.forward 里 x1/x2/x3 只上采样到 1/2 分辨率，res_weight(2ch) 再上采回全分辨率，融合分支显存可降 4 倍；④ 去重复张量。
- 注意：LSKNet 无 with_cp 支持，梯度检查点需改 backbone，非首选。
